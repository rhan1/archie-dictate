## Pipeline by stage

### a. CAPTURE

- **Desktop dictation capture uses the Electron renderer's getUserMedia and AudioWorklet**, requesting 16 kHz mono. The inspected default constraints disable echo cancellation, noise suppression, and automatic gain control. Requested sample rate does not prove the hardware's native rate. [E03 — .webpack/renderer/hub/index.js:1, byte ~651596, “echoCancellation:!1,noiseSuppression:!1,autoGainControl:!1,sampleRate:X_,channelCount:1”; byte ~648362, “J_=40,X_=16e3”; byte ~725781, “setupAudioWorklet”]
- **PCM becomes signed 16-bit samples in 40 ms packets**: 640 samples / 1,280 bytes at 16 kHz mono (inferred arithmetic). WebCodecs Opus uses 16 kHz mono at 64 kb/s, emitting packets labelled 20 ms. PCM remains available alongside Opus for fallback. [E04 — .webpack/renderer/hub/index.js:1, byte ~648362, “Z_={codec:\"opus\",sampleRate:X_,numberOfChannels:1,bitrate:64e3}”; byte ~648758, “new Int16Array”; byte ~735221, “new AudioData({format:\"s16\",sampleRate:X_”; near initOpusEncoder, “duration:20,encoding:\"opus\"”; byte ~735878, “duration:J_,encoding:\"wav\"”]
- **Opus is conditional, not a universal production default.** Encoder support and feature flags determine selection; the voice-actions realtime path excludes it. After two seconds of PCM without Opus packets, the client switches to PCM/WAV. The main-process opusEncoder worker also serves meeting recording and should not be mistaken for the dictation encoder. [E05 — .webpack/main/index.js:8, byte ~4316665, “TO.OpusEuAsiaExperimentV2”, “TO.UseOpus”, “&&!Q”; byte ~4234724, “No opus data received after 2 seconds of wav data, switching to wav”; byte ~5405223, meeting output “channels:2” and “format:\"opus\"”]
- **Volume/capture-health monitoring handles mute events, silent starts, and mic reopen recovery.** Warning/escalation thresholds are 125/375 PCM packets, or 5/15 seconds (inferred from 40 ms). This establishes silence detection, not neural VAD or speech-based endpointing. [E06 — .webpack/renderer/hub/index.js:1, byte ~652833, “SILENCE_WARNING_THRESHOLD_CHUNKS=125”, “SILENCE_ESCALATION_THRESHOLD_CHUNKS=375”; byte ~724519, “Reopening dictation mic after a silent start”; .webpack/main/index.js:8, byte ~4213040, “volumes,En.getCurrentFloor()”]
- **Mic selection includes physical-device ranking, explicit virtual-input selection, and changes applied to subsequent dictations.** Bluetooth startup can clip initial words; docs recommend comparing built-in/wired inputs. The renderer includes a bounded AirPods cleanup workaround that reacquires and stops a stream, with a three-second timeout. Its effectiveness was not tested. [E07: microphone selection](https://docs.wisprflow.ai/articles/8884408990-connect-and-set-up-external-audio-devices) [E08 — .webpack/renderer/hub/index.js:1, byte ~716622, “cleanupMediaStream”, “rf(lf.mediaOptions,3e3)”, “skipping AirPods workaround”]

### c. ASR

- **Recognition is cloud-based**, not an established on-device ASR path. Public engineering describes recognition conditioned on app context, relevant history, recurring terms, and voice embeddings; this describes their approach, not universal availability of every signal. These are supported identifiers, not proof of the active model/vendor/version or a production ensemble. “Scribe” alone does not establish ElevenLabs; “Whisper” does not establish a direct OpenAI API call. ### d. FORMATTING / AUTO-CORRECTION

### e. INSERTION

- **Normal desktop insertion uses clipboard/paste**, requiring macOS Accessibility permission. Helper strings show stored app/element focus and fallback handling. A special consent-chat path attempts a direct AX value write before clipboard fallback; it does not establish direct AX insertion or per-character typing for ordinary dictation. [E31: paste behavior](https://docs.wisprflow.ai/articles/7971211038-fix-text-not-pasting-after-dictation) [E32 — Helper strings near paste execution, “Attempting to focus stored app and element”, “Beginning regular pasteText.”, “ConsentChatMessage: direct AXValue set did not stick, falling back to clipboard paste”]
- **The helper supports delayed clipboard rendering and observes destination data requests** for success/failure handling. This is stronger than treating Cmd-V dispatch as proof of insertion (inferred). [E33 — Helper strings near DelayedClipboardProvider, “Using delayed clipboard rendering”, “Delayed clipboard data requested”, “Failed Timeout timer cancelled - paste succeeded (data was requested)”]
- **Restoration is conditional and timed:** around **500 ms** normally and **five seconds** for remote viewers, preserving newer user copies. Failed insertion can leave the transcript for manual paste. Unsupported types are not fully preserved; this is not a lossless clipboard guarantee. [E31: paste behavior](https://docs.wisprflow.ai/articles/7971211038-fix-text-not-pasting-after-dictation) [E34 — Helper strings near restoration, “Scheduling clipboard restoration in 500ms”, “Skipping clipboard restoration - shouldRestore is false”]
- **Raw/edited outputs remain recoverable**, including Undo AI edit without retranscription. Paste-last/copy-last controls recover transcripts after insertion failure. [E25: Auto Cleanup](https://docs.wisprflow.ai/articles/4283510616-auto-cleanup-control-how-much-flow-edits-your-dictation-beta) [E31: paste behavior](https://docs.wisprflow.ai/articles/7971211038-fix-text-not-pasting-after-dictation)

### f. UI / HOTKEY

- **Hold/release supports push-to-talk; a double-tap within half a second promotes hands-free.** Fn+Space starts hands-free separately; a later shortcut press or stop control finishes. A rapid third PTT tap or early hands-free double-press cancels. Macs without Fn use alternative combinations. ## What Wispr does that Dictate does not

Comparison uses the supplied Dictate description, not a repository audit.

- **Confirmed gap:** Wispr uses active app/site and cursor context; the supplied Dictate baseline explicitly uses neither. Local cursor finishing is a small first step. [E21; E22]
- **Difference:** Wispr sends vocabulary in initial backend preferences/context; Dictate's description places its vocabulary list in cleanup. Whether Dictate also sends ASR hints was not stated. [E18]
- **Difference:** Wispr's described cleanup uses fine-tuned Llama on optimized cloud serving; Dictate uses few-shot local llama3.2:3b with gpt-4.1-nano fallback. This does not prove cloud inference would beat Dictate on its target hardware/network. [E19; E41]
- **Difference:** Wispr supports hold/release and hands-free promotion; Dictate's stated gesture is double-tap Left Option to start and single tap to finish. [E35; E37]
- **Difference:** Wispr requests 16 kHz mono with optional Opus; Dictate streams 24 kHz pcm16. Changing codec/rate requires checking the ASR interface and measuring recognition loss. [E03; E04; E05]
- **Practices not described for Dictate, not proven absent:** per-app styles/cleanup levels, correction learning, deterministic snippets/replacements, observed clipboard consumption/restoration, geographic selection, bounded transport races, and stage-level tail metrics. [E24; E25; E27–E29; E31–E34; E43; E44; E47]
